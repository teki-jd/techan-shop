# 三、照片和初始数据怎么来

## 先说结论

| 你想拿的 | 能不能自动化拿到 | 我的建议 |
| --- | --- | --- |
| 图片 | 技术上能（抓包拿 CDN 链接），但**不建议** | 找朋友要原图，或自己拍 |
| 价格 | **不能**，只能人眼看 | 更不该抄，按自己的成本算 |
| 分类 | **不能**，只能人眼看 | 自己按"山货 / 鲜货 / 手工吃食"分就行，反而更适合你 |

## 为什么"从朋友的小程序下载图片和价格"不成立

### 1. 价格和分类真的读不到

小程序的数据不在代码里，存在他那边的云数据库（或者他的服务器）里。你打开他的小程序看到的是**已经渲染出来的页面**，代码包就算解包（wxapkg）也只有前端页面结构和接口地址，没有商品数据。
所以"批量导出他的商品"这件事，工具上不存在。你只能：截图 → 人眼看 → 手抄/打字。

### 2. 图片能抓，但有三个坎

技术上：小程序的图片是 CDN 链接（`https://xxx.tcb.qcloud.la/...`），用抓包工具（Charles / 开发者工具的 Network 面板）能看到，能下载。

但：
- **版权**：那是他拍的图。你拿去做自己的生意，哪怕货一样，也需要他同意。这是"一句话的事"，但不打招呼直接用，是同事/朋友关系里最容易翻车的地方。
- **质量**：小程序里展示的图是压缩过的（通常 750px 宽、webp），你放到详情页大图会明显糊，反而显得不专业。
- **规则**：批量抓取他人小程序内容违反《微信小程序平台运营规范》，风险落在**你的**小程序账号上（轻则警告，重则限制功能）。为了省两小时拍照，不值。

### 3. 更实际的做法（按推荐顺序）

**① 直接问朋友要原图**（最省事）
> "你那几张图拍得挺好，我也在卖同样的东西，能不能把原图发我几张？"

一般都会给，而且给的是手机相册原图——比小程序里清晰得多。顺手也把"能不能用"讲明白了，关系不至于别扭。

**② 自己拍**（最可靠，一上午能拍完 10 个品）
手机就够，不用相机。几个要点：
- **光**：白天靠窗、阴天最好（光线柔和不硬）。别开室内顶灯直射，会有黄光和硬阴影。
- **底**：一块素色布 / 木桌 / 白卡纸。别用花桌布。
- **角度**：45° 俯拍（有立体感）+ 一张正俯拍（看全貌）。
- **一定要拍的三张**：
  1. **主图**：单件/一袋，1:1，主体占 70%
  2. **分量参照**：手握一把、或者旁边放个一元硬币 / 一瓶水，让人知道"一斤有多少"
  3. **过程图**：晾晒、采摘、灶台、包装——**这张最带货**，比精修图管用
- **别过度美颜**：特产卖的是"真"，颜色失真反而被投诉。

**③ 拿朋友图当参考**（可以看，别直接用）
看他怎么写文案、怎么定价位、详情页放几张图。这是学习和竞品分析，不是复制。

## 价格：为什么必须自己算

抄他的价格，等于抄他的成本结构。你要算：

```
售价 ≥ 进货/自采成本 + 包装（袋子/箱子/冰袋）+ 快递费 + 损耗（尤其鲜货）
```

- 鲜货损耗按 5%~10% 预留（路上烂的、退的）。
- 快递费：省内/邻省/远省差别大，鲜货还要冷链。**所以小程序里干脆不写死运费**，让用户下单、你按地址报——这正是这个流程设计成"邮费待确认"的原因。
- 打包建议：标价写"含包装，不含运费"，运费单独报。

## 初始化数据的三条路

### 路径 A：在小程序里一个一个加（推荐，10~20 个商品）

管理后台 → 商品 → ＋ 新增商品 → 填名字/价格/单位/分类/介绍 → 传图 → 保存。

- 一个商品大概 2~3 分钟。**20 个商品 = 1 小时**。
- 手机上操作很快：选图可以一次多选 9 张。
- 分类不存在的话，先在云开发控制台的 `categories` 集合里加一条（或者用路径 B 导入分类）。

### 路径 B：CSV 批量导入（30 个以上商品时）

适合商品多、又不想一个个敲的场景。图片还是在小程序里补（批量上传到云存储并回填 fileID 太折腾，不值得）。

**步骤：**

1. 打开 `data/products.template.csv`，用 Excel / WPS / Numbers 编辑（也可以先用腾讯文档在线编辑，再导出 CSV）。
   列固定为：`商品名,分类,价格,单位,重量,标签,介绍`

2. 分类要一致。先看 `data/categories.import.jsonl`：
   ```
   {"_id":"cat-shanye","name":"山货干货","sort":3}
   {"_id":"cat-xianhuo","name":"时令鲜货","sort":2}
   {"_id":"cat-shoushi","name":"手工吃食","sort":1}
   ```
   想加分类就照这个格式加一行，`_id` 自己起个不重复的（`cat-xxx`），`sort` 越大越靠前。

3. 转成导入文件（需要电脑上装了 Node，本项目不需要装任何依赖）：
   ```bash
   cd techan-shop
   node scripts/csv2jsonl.js
   ```
   输出 `data/products.import.jsonl`。

4. 云开发控制台 → 数据库：
   - 先对 `categories` 集合点「导入」，选 `data/categories.import.jsonl`，格式选 **JSON**（每行一条）。
   - 再对 `products` 集合点「导入」，选 `data/products.import.jsonl`。
   - ⚠️ 如果之前点过「初始化店铺数据」，会有 4 个示例商品，先手动删掉，避免重复。

5. 回到小程序 管理后台 → 商品，逐个点「编辑」补图片。

### 路径 C：直接在云开发控制台加文档（不推荐）

字段容易漏（比如忘了 `onSale: true` 就不显示），`catId` 要填对面分类的 `_id`，容易错。除非只改一两个字段，否则别用。

## 商品字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | 文本 | 商品名，别太长，12 字以内最好 |
| `catId` | 文本 | 分类 `_id`，要和 `categories` 里的对上 |
| `catName` | 文本 | 分类名（冗余存一份，方便后台显示） |
| `price` | 数字 | **单价，元**，不要带 ¥ 符号，可小数 |
| `unit` | 文本 | 单位：`袋` / `盒` / `瓶` / `箱` / `份` / `斤`，回答"一份是一袋还是一盒" |
| `weight` | 文本 | 重量：`250g` / `500g` / `5斤`，可留空。老数据写成 `袋(250g)` 会自动拆开 |
| `desc` | 文本 | 介绍，可换行。写产地、口感、怎么存、怎么吃 |
| `cover` | 文本 | 封面图 fileID（`cloud://...`），空则列表显示文字占位 |
| `images` | 数组 | 详情图集，最多 9 张 fileID |
| `tags` | 数组 | 小标签，最多 6 个，如 `["自家晒","干货"]` |
| `sort` | 数字 | 越大越靠前 |
| `onSale` | 布尔 | `false` = 下架，首页不显示（历史订单不受影响） |

## 图片规格建议

- 比例 **1:1**（主图）或 4:3，宽度 **800~1000px** 足够，单张 **≤ 500KB**。
- 上传时选择"压缩"，小程序会自动处理。
- 别传 4000px 的原图：加载慢、烧流量（你的 CDN 流量是花钱的）。
- 建议每个商品 3~5 张图：主图 + 分量参照 + 过程/包装。

## 文案合规（顺手提醒）

- **不要写功效**：蜂蜜不能写"治咳嗽/养胃"，柿饼不能写"降火"，辣酱不能写"开胃健脾"。食品宣传涉及功效就是违规，容易被打假的盯上。
- **不要用绝对化用语**："最好吃""第一""纯天然无添加"这类都别写。写"自家晒的""柴火烘的""一年取一次"这类能验证的描述。
- **写清发货方式**：现摘现发 / 每周三统一发货 / 冷链加冰袋。减少你后面的解释成本。
