# 五、交接清单：把代码发给朋友去部署

## 你要发给他什么

只需要 **`server/` 这一个目录**（小程序前端不用给他，那是你上传到微信的）。

发之前先做三件事：

1. **删掉测试数据**：`server/data/db.json`（如果有）、`server/public/uploads/` 里的测试图。
2. **别把 `.env` 发出去**（里面是你的 AppSecret）。目录里只有 `.env.example`，他自己复制一份填。
3. 打包：
   ```bash
   cd techan-shop
   tar czf techan-server.tar.gz --exclude node_modules --exclude .env --exclude 'data/db.json' server
   ```
   或者直接把 `server/` 拖进微信/邮件发给他。

## 你要向他要 / 告诉他的信息

**你要给他：**
- 小程序的 **AppID**（mp 后台 → 开发管理 → 开发设置）
- 小程序的 **AppSecret**（同一页，可以重置；只给他，别发群）
- 这个后端要用的**域名**，例如 `api.example.com`

**你要告诉他：**
- 这是零依赖服务，**不用 npm install**，`node index.js` 就能起
- 部署步骤都在 `server/README.md`，照做即可
- 三个必须的配置：`APPID`、`APPSECRET`、`TOKEN_SECRET`（让他自己生成一串）
- 生产环境 `DEV_MODE=0`
- 3000 端口只对 127.0.0.1 开放，用 nginx 反代到 443
- 备份就备份 `data/db.json` + `public/uploads/`

**你要向他要回来：**
- 配好的访问地址：`https://api.example.com`（填进 `miniprogram/config.js` 的 `httpBase`）
- 确认 `curl -s https://api.example.com/api/health` 返回 `{"ok":true,...}`

## 他部署完之后，你做这几步

1. 改 `miniprogram/config.js`：
   ```js
   backend: 'http',
   httpBase: 'https://api.example.com',
   devOpenid: ''        // 必须清空
   ```
2. 小程序后台 → 开发管理 → 开发设置 → 服务器域名 → `request 合法域名` 填 `https://api.example.com`
3. 重新编译，首页点「初始化店铺数据」——**第一个点的人成为管理员**，所以这一下要你自己点，别让同事先点。
4. 走一遍 `docs/04-测试指南.md` 里的测试清单，重点看：图片能不能显示、电话能不能拨、后台能不能看到订单。
5. 提审 → 发布。

## 几个必须提前说清的坑

**① 域名没备案 = 正式版一定不通。**
微信要求调用域名必须 ICP 备案。开发阶段可以靠"不校验合法域名"和"打开调试"绕过，但正式版没有任何余地。
如果你朋友的服务器在国内，域名得备案（个人备案 1~3 周）；如果服务器在境外（香港、海外），域名理论上不需要备案，但访问速度慢、偶发不稳定，而且微信配域名时可能仍校验备案——**这条务必让他先试一遍再决定**。

**② 服务器一旦挂了，小程序就白屏。**
云开发的好处是"微信不会挂"，自建的代价是你得盯着。所以：
- 让他配 `pm2` 守护 + 开机自启
- 加个每天备份的定时任务
- 年前年后这种单量高峰，提前跟他说一声别重启机器

**③ 这是个"朋友帮忙"，不是"托管服务"。**
代码我给了他，但系统出问题、证书到期、磁盘满了，都是他的活。把这几点说在前面，比出事之后再吵好。

**④ 你自己的小程序主体是个人。**
个人主体 + 自建服务器，技术上没问题，但**类目审核那条线没变**：食品类目仍然要资质，工具类目仍然可能被判定类目不符。换后端不改变这件事。

## 如果哪天想搬回云开发

代码是同一套业务逻辑，`config.js` 里把 `backend` 改回 `'cloud'`、把 `cloudfunctions/shopapi` 部署上去就行。数据不通用（一个在 JSON 文件、一个在云数据库），量小的时候直接重新初始化最快。
